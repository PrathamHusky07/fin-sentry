# Build Log

## 2026-09-07 — Day 1 (partial: steps 1 and 2 of 6)

**Step 1 — Project scaffold and gateway skeleton.** Created the `finsentry/` package with `finsentry/gateway/main.py` — a FastAPI app that exposes `GET /health` returning `{"status": "ok"}` and `POST /v1/chat/completions` as a transparent async proxy to a configurable downstream URL. Added `pyproject.toml` with ruff, mypy strict, and pytest config, `requirements.txt` for Day 1 deps, and `.env.example`. The package is named `finsentry`, not `platform`: Python's stdlib ships a `platform.py` module, and any local package named `platform` shadows it, breaking `platform.python_version()` in pytest's terminal reporter and causing an import error on collection. All three checks pass clean: `ruff check .`, `mypy finsentry/`, `pytest -x -q`.

**Step 2 — Docker Compose stack.** `docker-compose.dev.yml` brings up Postgres 16 on port 5432, Redpanda v26.2.2 in dev-container mode with `--smp 1` on port 9092, and RisingWave v3.0.3 in playground mode on port 4566. All three services have healthchecks and all three show `(healthy)` in `docker compose ps` STATUS before reporting ready. Images are pinned to specific version tags (not `:latest`) so a future `docker pull` cannot silently change behavior. Verified: `rpk cluster info` returns broker metadata, `SHOW TABLES` on RisingWave succeeds, `psql` to Postgres connects and runs `\dt` without error. Known issue: RisingWave v3.0.3 in playground mode crashes after roughly five hours due to a worker heartbeat expiry (the meta service deletes the worker registration and the frontend loses contact). The container recovers on a fresh restart. Watch for this on Day 4 when the streaming worker pool is introduced.
